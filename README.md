# AmneziaWG 3.1 VPS Auto Installer — v1.1

Автоматическая установка **AmneziaWG 3.1 + amneziawg-web + nginx + Let's Encrypt** на **чистую Ubuntu 24.04 LTS**.

> **Статус:** проходит статические проверки (Bash/ShellCheck и инварианты). Полный запуск на VPS и внешний handshake ещё не проверены. Это инструмент для чистого тестового VPS, а не гарантированно готовый production-инсталлятор.

## Требования

- Чистая Ubuntu 24.04 LTS с публичным IPv4 и root по SSH.
- Открытые у хостера порты: **22/TCP**, **80/TCP**, **443/TCP**, выбранный UDP (по умолчанию **585/UDP**).
- Поддерживается VPS с 1 GiB RAM: при недостатке swap установщик создаёт постоянный файл `/swapfile` размером 2 GiB и ограничивает сборку Cargo одним заданием. Нужно **не менее 6 GiB свободного места** перед началом установки; практически лучше 10 GiB или больше. Если `/swapfile` уже существует, но swap недостаточно, установщик остановится для ручной проверки.
- Доступ VPS к GitHub, apt-репозиториям Ubuntu, Snap Store и Let's Encrypt.
- До начала убедитесь, что VPS не содержит другой установки VPN, nginx-конфигурации `awg31` и важных данных.

## Быстрый запуск

На **новом** VPS, с правами root:

```bash
curl -fL https://raw.githubusercontent.com/bighaired/awg31-vps-autoinstall/main/install.sh -o /root/awg31-install.sh
bash -n /root/awg31-install.sh
less /root/awg31-install.sh
bash /root/awg31-install.sh
```

**Пока PR не объединён**, для тестирования v1.1 используйте ветку `feature/v1.1-hardening-ci` вместо `main` в URL скачивания.

Скрипт запросит публичный IPv4, порт UDP, email для Let's Encrypt, имя администратора и пароль длиной от 16 символов. Пароль вводится скрыто через `/dev/tty` — символы и звёздочки не отображаются. При прерванном вводе скрипт выводит ошибку, а не завершает работу молча. На первом этапе сервер установит пакеты и **автоматически перезагрузится**. После загрузки systemd продолжит установку.

Никогда не запускайте произвольный скрипт из сети с root-правами без проверки его содержимого.

## Что изменилось в v1.1

- **Закреплённый upstream:** оба установщика Wiresock берутся из коммита `1e0b321f9b481ab21ee68ca709c5ca84ab68041f` от 03.11.2026, а не из постоянно изменяемой ветки `main`. Обновлять upstream следует отдельно после ревью.
- Улучшена диагностика сбоев. Если этап после перезагрузки завершился ошибкой, его можно повторить без повторного ввода параметров.
- Первичные резервные копии `params` и `awg0.conf` сохраняются и не перезаписываются при повторном запуске.
- Прерванная загрузка исходников Wiresock может быть повторена без удаления `.git`, включая ситуацию, когда репозиторий инициализирован, но `origin` ещё не добавлен.
- При частичной установке панели скрипт повторяет установку, если отсутствует бинарник, файл окружения или systemd unit, и проверяет логин, хеш пароля и привязку к localhost.
- `S1`–`S4` выравниваются по исходному `S4`, чтобы сохранить рассчитанный установщиком бюджет MTU и не создавать фрагментацию из-за смены размера транспортного padding.
- Добавлена проверка systemd-таймера автоматического продления TLS-сертификата.
- Добавлены `.gitignore`, GitHub Actions (Bash, ShellCheck и статические контракты).
- Сохранён безопасный bind Web-панели только на `127.0.0.1:8080`.
- Для VPS на 1 ГБ RAM добавлены предварительная настройка swap и ограничение параллелизма сборки Rust.

## Проверка и восстановление после перезагрузки

```bash
systemctl status awg31-autosetup --no-pager
journalctl -u awg31-autosetup -n 100 --no-pager
tail -n 100 /var/log/awg31-autosetup.log
systemctl is-active awg-quick@awg0 amneziawg-web nginx
awg show
```

Если в логе есть ошибка, **исправьте причину**, затем продолжите:

```bash
systemctl restart awg31-autosetup
```

Это возобновление **best-effort**, а не транзакционный откат. Не удаляйте вручную `/var/lib/awg31-autosetup/config` до успешного завершения. После успеха конфигурация первоначальной установки удаляется, фиксируется `upstream-commit`, сервис автодоустановки отключается.

## После установки

- Web-панель: `https://ПУБЛИЧНЫЙ_IP/`.
- Проверьте выпуск TLS-сертификата и автоматическое продление.
- Создайте тестового клиента в панели, импортируйте его конфигурацию в **совместимый с AWG 3.1** клиент и проверьте **handshake** и обмен трафиком из внешней сети.
- Убедитесь, что в firewall хостера разрешён UDP на выбранном порту, а 8080/TCP **не открыт наружу**.

Для диагностики:

```bash
awg show
ss -lunp
ss -lntp
journalctl -u awg-quick@awg0 -n 100 --no-pager
```

Локальная проверка сокета UDP не доказывает доступность сервера из России. Изолированный автоматический тест внешнего handshake невозможен без независимого внешнего клиента.

## Безопасность

- Не добавляйте в GitHub: конфигурации клиентов, приватные ключи, `env.conf`, сертификаты, `awg-vars`, backup-файлы и логи.
- Параметры установки записываются в root-only файл `/var/lib/awg31-autosetup/config` (права 0600); пароль хранится как Argon2id-хеш. Введите пароль только непосредственно на VPS.
- HTTPS-панель находится за nginx; непосредственно Web-панель слушает только localhost.
- Скачиваемые сторонние установщики запускаются с правами root. Пин коммита ограничивает неожиданные изменения, но **не заменяет аудит стороннего исходного кода**.

## CI

Workflow `.github/workflows/ci.yml` запускает `bash -n`, ShellCheck, Python-проверки статических инвариантов и выполнение парсеров S4 и UDP-сокета на синтетических входных данных на push и pull request. **CI не устанавливает VPN на реальный VPS и не подтверждает доступность UDP или работоспособность подключения клиента**.
