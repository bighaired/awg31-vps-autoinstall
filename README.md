# AmneziaWG 3.1 + Web-панель HTTPS — автоматическая установка на VPS

Установка **AmneziaWG 3.1, amneziawg-web, nginx и сертификата Let's Encrypt для публичного IPv4** на **чистую Ubuntu 24.04 LTS**. Запуск выполняется одной командой под `root`; установщик задаёт несколько вопросов, перезагружает сервер и автоматически продолжает работу через systemd.

**Статус проверки:** 5 ноября 2026 года установка успешно завершена на реальном VPS с Ubuntu 24.04 и 1 GiB RAM: получен сертификат Let's Encrypt, запущены AWG 3.1 и HTTPS-панель, в журнале получено `SUCCESS`. Вход в панель проверен. **Доступность UDP извне, handshake и прохождение VPN-трафика отдельным клиентом нужно проверить самостоятельно.** CI проверяет синтаксис и инварианты, но не заменяет полный интеграционный тест.

## 1. Требования

- **Новая установка Ubuntu 24.04 LTS** (не 26.04), `root` и интерактивный SSH-сеанс. На уже настроенном сервере скрипт намеренно не перезаписывает существующий VPN или Web-панель.
- Публичный IPv4, доступность GitHub, репозиториев Ubuntu, Snap Store и Let's Encrypt с самого VPS.
- Разрешённые у хостера порты: **22/TCP (SSH), 80/TCP (проверка и продление сертификата), 443/TCP (HTTPS-панель), 585/UDP (VPN)** — либо выбранный вами UDP-порт.
- VPS с **1 GiB RAM** поддерживается. При недостатке памяти/swap скрипт добавит собственный swap-файл **2 GiB**, не затрагивая имеющийся `/swapfile`. Для этого требуется **не менее 6 GiB свободного диска**; рекомендуем больше 10 GiB.
- Рабочий **email, набранный латиницей** (только ASCII), для регистрации в Let's Encrypt. Перед адресом не должно быть пробелов или кириллических символов.

## 2. Установка одной командой

Подключитесь к новому VPS по SSH под `root`, затем **скопируйте и выполните одну команду**:

```bash
curl -fsSL https://raw.githubusercontent.com/bighaired/awg31-vps-autoinstall/main/install.sh -o /root/awg31-install.sh && bash -n /root/awg31-install.sh && bash /root/awg31-install.sh
```

Команда скачивает установщик в локальный файл, проверяет синтаксис Bash и запускает его. **Это одна команда запуска, а не установка без вопросов.** Вы можете прочитать исходник [install.sh](install.sh) перед запуском; скрипт выполняется с правами root.

Ответы на вопросы:

| Запрос | Что вводить |
|---|---|
| `Public IPv4 (Enter = detect automatically)` | **Enter**, если IP определяется правильно |
| `AmneziaWG UDP port [585]` | **Enter** для `585/UDP` |
| `Email for Let's Encrypt notices` | Действующий email **латинскими буквами**, например `user@example.com` |
| `Web panel username [admin]` | **Enter** для `admin` или свой логин |
| `Web panel password` | Уникальный пароль (минимум 6 символов; **рекомендуется длиннее**) |
| `Repeat password` | Повторить пароль |
| `Start unattended installation ... [y/N]` | `y` и **Enter** |

Пароль вводится **невидимо**, без звёздочек. После подтверждения сервер скачает зависимости, подготовит swap при необходимости и **перезагрузится**. SSH-соединение оборвётся — это нормально. **Повторно запускать команду установки после перезагрузки не нужно**: служба `awg31-autosetup.service` продолжает работу автоматически. На 1 GiB RAM компиляция Rust может занять заметное время.

## 3. После автоматической перезагрузки

Повторно подключитесь к серверу по SSH и следите за установкой:

```bash
journalctl -fu awg31-autosetup
```

**`Ctrl+C` закрывает только просмотр журнала**, а не останавливает установку через systemd.

Успешное окончание определяется по записи вида:

```text
SUCCESS: web panel https://<PUBLIC_IP>/ ; login admin; AWG UDP port 585
```

Откройте `https://<PUBLIC_IP>/` в браузере. Логин и пароль — введённые при установке. Панель непосредственно слушает **только** `127.0.0.1:8080`, наружу опубликован nginx на `443/TCP`.

Для быстрой проверки:

```bash
systemctl status awg31-autosetup --no-pager
systemctl is-active awg-quick@awg0 amneziawg-web nginx
awg show
certbot certificates
```

После успешного завершения служба автодоустановки **отключается** (поэтому статус может быть `inactive`, а не `active`); три службы VPN, панели и nginx должны работать.

## 4. Что именно устанавливается

- Сервер **AmneziaWG 3.1**, интерфейс `awg0`, UDP-порт 585 по умолчанию.
- Зафиксированная версия [Wiresock awg-server-tools](https://github.com/wiresock/awg-server-tools) — коммит `1e0b321f9b481ab21ee68ca709c5ca84ab68041f` (не плавающий upstream `main`).
- **amneziawg-web** с авторизацией (хеш пароля Argon2id) и локальным bind `127.0.0.1:8080`.
- **nginx** как HTTPS reverse proxy.
- **Let's Encrypt IP-сертификат краткого срока действия** (на проверенном запуске — около 6 дней), Certbot с заданием автоматического продления. Порт **80/TCP должен оставаться доступным** для HTTP-01 проверки при продлении.
- Выравнивание `S1`–`S4` по первоначальному `S4`, с сохранением рассчитанного бюджетa MTU. Не увеличивайте MTU вручную из-за предупреждения в панели: старые версии WireSock могут повторно вычитать `S4`.

## 5. Если установка завершилась с ошибкой

**Не переустанавливайте Ubuntu и не запускайте начальный `install.sh` заново.** Посмотрите причину:

```bash
journalctl -u awg31-autosetup -n 100 --no-pager
tail -n 100 /var/log/awg31-autosetup.log
```

После устранения ошибки возобновите установку сохранённой копией:

```bash
systemctl reset-failed awg31-autosetup && systemctl restart --no-block awg31-autosetup && journalctl -fu awg31-autosetup
```

Если ошибка исправлена в **новой версии установщика** на GitHub, обновите сохранённую копию перед возобновлением:

```bash
curl -fsSL https://raw.githubusercontent.com/bighaired/awg31-vps-autoinstall/main/install.sh -o /root/awg31-install.sh && bash -n /root/awg31-install.sh && install -m 700 /root/awg31-install.sh /usr/local/sbin/awg31-autosetup && systemctl reset-failed awg31-autosetup && systemctl restart --no-block awg31-autosetup && journalctl -fu awg31-autosetup
```

*Важно:* после первой перезагрузки systemd использует файл **`/usr/local/sbin/awg31-autosetup`**, а не исходный файл в `/root`. Одного скачивания новой версии недостаточно; поэтому команда выше обновляет и установленную копию. При сомнениях проверяйте наличие нужной исправленной строки в скачанном файле до рестарта или используйте URL конкретного проверенного коммита GitHub.

### Типовые ошибки, выявленные при реальной установке

| Симптом | Причина и действия |
|---|---|
| `Could not resolve host: github.com` после перезагрузки | Сеть/DNS может быть не готова. Установщик повторяет `git fetch` до 6 раз. При устойчивой ошибке проверьте `resolvectl query github.com` и `curl -I https://github.com`. |
| `Existing /swapfile detected` | Ошибка старой версии: нельзя перезаписывать swap хостера. Текущая версия создаёт отдельный `/var/lib/awg31-autosetup/build.swap`. |
| `HOME: unbound variable` | Ошибка старой версии в systemd: исправлено заданием `HOME=/root` и пути Rust. |
| `Web panel not bound to localhost:8080` | Старая проверка срабатывала слишком рано. Теперь установщик ожидает до 30 секунд и при ошибке выводит журнал панели. |
| `invalidContact`, `contact email contains non-ASCII characters` | В сохранённом email есть кириллица/лишние символы. Исправьте строку `EMAIL=` в `/var/lib/awg31-autosetup/config` (файл доступен только root), затем возобновите установку. Остальные строки не меняйте. |
| Let's Encrypt `403 Forbidden` при HTTP-01 | У каталогов `/var/www/html/.well-known` и `acme-challenge` ранее были права `700` из-за `umask 077`. Теперь выставляются `755` и выполняется локальная HTTP-проверка до Certbot. |

При исправлении email редактируйте конфигурацию аккуратно:

```bash
nano /var/lib/awg31-autosetup/config
```

Не публикуйте этот файл целиком: он содержит служебные параметры и хеш пароля. Сохранённая конфигурация начальной установки **удаляется после успешного завершения**. Возобновление является *best-effort*, а не транзакционным откатом.

## 6. Изменение внутренней IPv4-подсети после установки

При двух VPN-серверах на одном роутере (например, **Keenetic**) стандартная подсеть AWG `10.66.66.0/24` может совпадать. Для одновременной работы измените подсеть **только второго VPS**, например на `10.77.77.0/24`. Публичный IP сервера, HTTPS и UDP-порт менять не требуется.

**Область применения:** инструкция ниже рассчитана на AWG-интерфейс `awg0`, исходный адрес сервера `10.66.66.1/24` и **отсутствие созданных клиентов (пиров)**. Не применяйте блок к серверу с действующими клиентами: их адреса, конфигурации, серверные `AllowedIPs` и записи Web-панели потребуется мигрировать согласованно. Новая подсеть не должна пересекаться с LAN и другими маршрутами.

### 6.1. Проверка перед изменением

Войдите на **изменяемый VPS** под `root` и проверьте:

```bash
grep '^SERVER_AWG_IPV4=' /etc/amnezia/amneziawg/params
grep '^Address[[:space:]]*=' /etc/amnezia/amneziawg/awg0.conf
grep -E '^Post(Up|Down)' /etc/amnezia/amneziawg/awg0.conf
awg show awg0 peers
```

В ожидаемом случае первый файл содержит `SERVER_AWG_IPV4='10.66.66.1'`, второй — `Address = 10.66.66.1/24`, а список пиров пуст. Если в `PostUp`/`PostDown` явно указана старая подсеть, потребуется отдельно изменить и эти правила; приведённый ниже блок для такой конфигурации не подходит.

### 6.2. Смена адреса с резервными копиями

Выполните на **втором VPS**, где ещё нет клиентов, следующий блок целиком:

```bash
set -e
PARAMS=/etc/amnezia/amneziawg/params
CONF=/etc/amnezia/amneziawg/awg0.conf

# Проверяем исходный адрес и отсутствие пиров
grep -Fxq "SERVER_AWG_IPV4='10.66.66.1'" "$PARAMS"
grep -Fxq 'Address = 10.66.66.1/24' "$CONF"
test -z "$(awg show awg0 peers)"
if grep -Eq '^AllowedIPs[[:space:]]*=' "$CONF"; then
  echo 'В конфигурации есть пиры; требуется ручная миграция' >&2
  exit 1
fi
if grep -E '^Post(Up|Down)' "$CONF" | grep -qF '10.66.66.'; then
  echo 'Правила firewall ссылаются на старую подсеть' >&2
  exit 1
fi

# Создаём резервные копии, не заменяя предыдущие
test ! -e "$PARAMS.before-subnet-change"
test ! -e "$CONF.before-subnet-change"
cp -a "$PARAMS" "$PARAMS.before-subnet-change"
cp -a "$CONF" "$CONF.before-subnet-change"

sed -i "s/^SERVER_AWG_IPV4=.*/SERVER_AWG_IPV4='10.77.77.1'/" "$PARAMS"
sed -i 's|^Address = 10\.66\.66\.1/24$|Address = 10.77.77.1/24|' "$CONF"
systemctl restart awg-quick@awg0

grep '^SERVER_AWG_IPV4=' "$PARAMS"
ip -4 addr show awg0
systemctl is-active awg-quick@awg0
```

Ожидается адрес интерфейса `10.77.77.1/24` и статус `active`. Если при перезапуске возникла ошибка, **не создавайте клиентов**, пока не проверите состояние службы. Для отката (если новых клиентов ещё не создавали):

```bash
cp -a /etc/amnezia/amneziawg/params.before-subnet-change /etc/amnezia/amneziawg/params
cp -a /etc/amnezia/amneziawg/awg0.conf.before-subnet-change /etc/amnezia/amneziawg/awg0.conf
systemctl restart awg-quick@awg0
```

### 6.3. Новый клиент и Keenetic

В Web-панели изменённого VPS создайте нового клиента и **скачайте новый** `.conf`. Проверьте, что он содержит адрес из новой подсети, например `Address = 10.77.77.2/32`, и `Endpoint = ПУБЛИЧНЫЙ_IP_ВТОРОГО_VPS:585`. Фактический адрес клиента может оканчиваться не на `.2`.

Если панель выдаёт старый адрес `10.66.66.x`, не импортируйте такой файл: сначала проверьте серверные параметры. Старые клиентские конфигурации нужно заменить.

В **Keenetic** создайте отдельное подключение для второго VPS. Разные подсети устраняют конфликт внутренней адресации, но при пересекающихся `AllowedIPs` (например, `0.0.0.0/0` в обоих профилях) необходимо дополнительно проверить политики маршрутизации. Затем проверьте handshake и передачу трафика через оба VPN.

## 7. Проверка клиента и сертификата

После входа в панель создайте нового клиента в интерфейсе Web-панели. Импортируйте его в **совместимый с AmneziaWG 3.1** клиент, подключитесь через **независимую внешнюю сеть** (например, мобильный интернет), проверьте handshake, внешний IP и передачу данных. Успешная установка сервера **сама по себе не подтверждает VPN-подключение**.

Краткосрочный сертификат требует работоспособного продления. Проверяйте:

```bash
certbot certificates
systemctl list-timers --all | grep -E 'certbot|snap.certbot'
```

Планировщик Certbot настроен, но его фактическое успешное продление нужно подтвердить после первого цикла. Не закрывайте **80/TCP**, пока используете HTTP-01.

## Безопасность и ограничения

- Не публикуйте конфигурации клиентов, приватные ключи, `/etc/amneziawg-web/env.conf`, содержимое `/var/lib/awg31-autosetup/config`, полные серверные логи и резервные копии.
- Сохраняемый пароль панели представлен **Argon2id-хешем**, конфигурация установки имеет права `0600`.
- **8080/TCP не открывайте наружу.** Используйте только HTTPS через nginx на `443/TCP`.
- Сторонние установщики из зафиксированного репозитория Wiresock работают с правами root: закрепление SHA уменьшает риск непредвиденных изменений, но не заменяет аудит.
- Это установка на чистую Ubuntu 24.04; автоматического обновления всего сервера или гарантий обхода сетевых ограничений нет.
